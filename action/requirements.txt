# The union of what the analysis and remediation services need to run in one process, except for
# the Semgrep CLI. The scanner lives in its own virtualenv from the analysis service's canonical
# requirements-scanner.txt.
#
# The two services pin some packages at different patch versions, which pip cannot satisfy from
# two files at once. Where they differ the higher pin wins, which is the analysis service's in
# every current case. tests/test_requirements_parity.py reads both service requirement files and
# fails if this list drops a package or pins one below what a service asked for.
#
# Some of the remediation service's dependencies are deliberately absent.
#
# google-cloud-storage and psycopg back its Postgres execution store, and kubernetes and
# google-cloud-run back the production sandbox drivers. None of the four is on the import path
# of the engine as the action runs it. Leaving them out keeps the image smaller and, more
# usefully, means the action cannot reach a database, a cluster or a Cloud Run job even by
# accident: a review that runs in someone else's CI verifies in that runner or not at all.
#
# Semgrep pins an older OpenTelemetry line than the remediation service. Installing its CLI in a
# separate environment keeps its dependency graph from downgrading the application runtime. Only
# the scanner executable is put on PATH; its Python and libraries never replace this environment.
